# Планшет Плеер + media-server

Проект из двух частей:

- **app/** — Android-приложение (плеер на libVLC) для старого планшета (Android 4.4.2, API 19, armeabi-v7a).
- **server/** — Rust-бинарник `media-server` для второго (root) устройства (aarch64), отдаёт файлы по локальной сети.
- **magisk/** — шаблон Magisk-модуля для автозапуска сервера без монтирования в систему.

## Сервер (media-server)

Запуск вручную на root-устройстве:

```
./media-server -H 0.0.0.0 -p 10930 -r /storage -n "Гостиная"
```

Параметры (также через переменные окружения MEDIA_HOST/MEDIA_PORT/MEDIA_ROOT/MEDIA_NAME/MEDIA_BACKGROUND/MEDIA_DATA_DIR):

| Флаг | Описание | По умолчанию |
|------|----------|--------------|
| `-H, --host` | адрес прослушивания | `0.0.0.0` |
| `-p, --port` | порт (TCP и UDP) | `10930` |
| `-r, --root` | корневая папка | `/storage` |
| `-n, --name` | имя сервера для автообнаружения | `media-server` |
| `-b, --background` | фоновый режим (без консоли) | выкл. |
| `-d, --data` | папка данных (allowed.json / access.log) | рядом с бинарником |

Корневая папка по умолчанию — `/storage`, чтобы были видны и внутренняя память (`/storage/emulated/0`), и карта памяти (`/storage/####-####`). Файлы данных (список разрешённых и лог) хранятся рядом с бинарником — в Magisk-модуле это папка модуля.

### Маскировка и защита

Сервер не раскрывает ни модель устройства, ни назначение. Для любого «чужого» запроса (не от одобренного планшета) он отвечает как обычный веб-сервер-заглушка:

- заголовок `Server: nginx/1.18.0 (Ubuntu)` и типовая HTML-страница nginx;
- никакой технической информации о планшете или Android не выдаётся;
- настоящие эндпоинты (`/list`, `/search`, `/download`) для них невидимы — только заглушка.

Автообнаружение по UDP при этом работает — планшет найдёт сервер в сети (ответ только на специальный широковещательный запрос `MEDIA_DISCOVER`, без деталей об устройстве).

При первом обращении нового устройства сервер спрашивает в консоли:

```
=== Запрос доступа ===
Устройство: "Samsung SM-T230"  (IP 192.168.0.55, id a1b2c3…)
Разрешить? [y/n] (30 сек):
```

- `y` — разрешить, `n` — отклонить. Нет ответа 30 сек — автоматический отказ.
- При подтверждении приложение создаёт случайный идентификатор записи и отдельный 256-битный ключ. Идентификатор не является секретом и сам по себе доступ не даёт.
- Обычные API-запросы подписываются HMAC-SHA256 с временем и одноразовым nonce; повтор такой подписи сервер отклоняет.
- Поток libVLC получает HMAC-подпись конкретного URL файла со сроком действия 24 часа. Секрет после успешной привязки в URL не передаётся.
- Разрешённые устройства и их ключи сохраняются в `allowed.json` (в папке данных).
- В фоновом режиме (`-b`, как в Magisk) пускаются только устройства с действующим ключом из `allowed.json`, остальным — заглушка.
- Параметры авторизации удаляются из консольного вывода и `access.log`; попытки чужих запросов продолжают записываться в журнал.

Команды консоли во время работы: `list` — список разрешённых, `revoke <id|имя>` — отозвать, `help` — справка.

### API (только для одобренных устройств)

- `GET /list?path=<отн>` — содержимое папки (JSON).
- `GET /search?q=<текст>[&path=<отн>]` — рекурсивный поиск (до 500 результатов; также ограничены глубина, число просмотренных записей и время обхода).
- `GET /download?path=<отн>` — отдача файла с поддержкой Range (перемотка/докачка).

Приложение добавляет к запросам HMAC-подпись. Для обычных запросов используются заголовки `X-Auth-*`; для потока libVLC — подписанные query-параметры. Копирования открытого идентификатора устройства недостаточно.

## Magisk-модуль (автозапуск)

Папка `magisk/` — шаблон модуля (`id=api_plaer`). CI собирает из него готовый zip с вложенным бинарником.

- **Не монтируется в систему** — только запускает сервер через `service.sh` после загрузки.
- Бинарник, `allowed.json`, `access.log` и `config.env` лежат в папке модуля `/data/adb/modules/api_plaer/`.
- Настройки запуска — в `config.env` (MEDIA_HOST/PORT/ROOT/NAME/BACKGROUND).
- При обновлении модуля `customize.sh` сохраняет `config.env` и `allowed.json` (список разрешённых не теряется; `access.log` может быть перезаписан).

> Первый раз разрешить планшет нужно интерактивно: запустите бинарник вручную через `su` (без `-b`), откройте сервер в приложении и подтвердите доступ `y` — после этого фоновый автозапуск будет пускать его автоматически.
>
> После обновления со старой версии существующие записи `allowed.json` не содержат ключа. Один раз запустите новый сервер без `-b` и подтвердите безопасную перепривязку; удалять историю приложения не требуется. После команды `revoke` приложение при следующем обычном API-запросе автоматически предложит перепривязку через консоль сервера.

## Приложение

- Главный экран: IP и порт, кнопка **Найти серверы в сети** (автообнаружение по UDP), список недавних подключений. Клавиатура не всплывает при запуске.
- Проводник: поиск, сортировка по имени (естественная, Серия 2 раньше Серии 10), потянуть вниз — обновить, отметка «✓» на просмотренных, метка «⏱» — есть место остановки, «⬇» — уже скачано.
- Навигация по папкам — «хлебные крошки» (путь с кликабельными сегментами) вверху.
- Кнопка «← Серверы» возвращает из корня проводника на экран подключения без перезапуска приложения.
- **Кнопка «Загрузки»** на панели проводника (как в старом Chrome) открывает отдельный экран с уже скачанными файлами (просмотр/удаление только своих загрузок).
- Скачивание через foreground-сервис с прогрессом в шторке; сразу после запуска — плашка «ОТМЕНИТЬ» (на случай случайного нажатия), отмена также из уведомления. Файлы хранятся по серверу и полному удалённому пути, поэтому одинаковые имена из разных папок не смешиваются; незавершённые загрузки используют отдельный `.part`-файл.
- APK можно скачать и сразу предложить установку («Скачать и установить») — для обновления самого плеера на старом планшете.
- Плеер: имя файла сверху по центру при показе управления, продолжение с места остановки (позиция сохраняется не чаще раза в 10 секунд и очищается после завершения), скорость, соотношение сторон и полноэкранный режим.
- Для новой серии плеер последовательно загружает временный кэш. `min(30%, 300 МБ)` остаётся максимальной целью, но воспроизведение может начаться раньше, если уже есть безопасный запас и измеренная скорость устойчиво превышает битрейт видео. Через 30 секунд приложение выбирает локальный режим или прямой libVLC по фактической скорости.
- После начала просмотра фоновая запись ограничивается примерно двойной скоростью потребления только при запасе более 90 секунд, чтобы не отнимать процессор и накопитель у видеодекодера. Общий планировщик отдаёт приоритет текущему видео, затем метаданным, ручным загрузкам и только потом предзагрузке очереди; приложение использует не более трёх управляемых файловых соединений одновременно.
- Загруженная часть показывается светло-серым вторичным заполнением основной полосы перемотки. После запуска прогресс загрузки сворачивается в полупрозрачную плашку справа сверху. После достижения 100% плеер переходит с Java HTTP-прокси непосредственно на локальный файл, сохраняя позицию.
- Если подготовка медленная, не хватает места, контейнер несовместим с растущим файлом или сохранённая позиция дальше 10 минут или 10% известной длительности, автоматически используется прежнее прямое воспроизведение libVLC. При дальней перемотке в режиме кэша плеер ждёт последовательную загрузку нужного участка без нового удалённого Range-запроса.
- После возврата из фона видеоповерхность libVLC подключается заново; выбранное масштабирование повторно применяется после поворота. Верхние 20% экрана исключены из жестов плеера, чтобы не мешать системным шторкам.
- Кнопки «предыдущая/следующая серия»; по окончании — окно со списком остальных серий и автопереходом. Для вручную выбранной очереди после полной загрузки текущей серии одним последовательным потоком заранее загружаются следующие три серии.
- Имена-копии сортируются после оригинала: `Серия.mp4`, затем `Серия (1).mp4`, `Серия (2).mp4`; ручной порядок выбранной очереди не меняется.
- Каждый новый источник получает отдельный экземпляр MediaPlayer и номер поколения, поэтому поздние события старой серии игнорируются. Долгое нажатие кнопки масштаба переключает аппаратный/программный декодер; после неудачного восстановления видеоповерхности программный режим пробуется автоматически. Диагностика сохраняется в `tablet_player_playback.log`.
- **При обрыве сервера плеер не выходит**: показывает статус «Поиск сервера…», переобнаруживает сервер по UDP (даже если сменился IP) и продолжает тот же файл с той же позиции.
- Настройки: светлая/тёмная тема.

## Сборка

Сборка автоматически в GitHub Actions (`.github/workflows/build.yml`):

- `server` — собирает `media-server` (aarch64) и Magisk-модуль. Артефакты: `media-server-aarch64`, `media-server-magisk`.
- `server-selftest` — проверяет, что чужим отдаётся ровно один заголовок `Server: nginx` (маскировка без дубликатов).
- `app` — собирает APK. Артефакт: `tablet-player-apk`.
