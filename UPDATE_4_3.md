# Обновление 4.3

## Сглаживание во время просмотра

В настройках добавлен переключатель «Сглаживание до 60 FPS», по умолчанию выключенный.
При включении плеер определяет частоту выбранной видеодорожки каждой серии через libVLC.
При отсутствии частоты в метаданных фоновый MediaExtractor анализирует не более 180
временных меток сжатых видеосэмплов. Метки сортируются для видео с B-кадрами.
Неизвестная частота или неудачный анализ приводят к обычному воспроизведению.
Анализ не использует скорость работы декодера как частоту исходного видео.

Для источников строго ниже 50 FPS применяется дополнение до 60 FPS. При 50 FPS и выше
используется обычный вывод. Если ускорение воспроизведения уже повышает частоту до 50
кадров/с или выше, дополнительное смешивание отключается.

Новый вывод использует SurfaceTexture, EGL и OpenGL ES 2.0; минимальная версия Android
остаётся 4.4 / API 19. libVLC сохраняет управление декодером, звуком, потоками и субтитрами.
Кадры не читаются на CPU и не кодируются в новый файл. В GPU хранятся две текстуры;
их размер ограничен размером вывода и 1280 пикселями по большей стороне.
Вывод идёт по сигналам vsync с ограничением до 60 FPS. Коэффициент смешивания считается
по времени, поэтому 24/25/29,97 FPS обрабатываются без фиксированного множителя ×2.

Алгоритм — облегчённое адаптивное смешивание кадров, без optical flow и нейросетевой
оценки движения. Он может дать более мягкое движение, но также двойные контуры;
повышение числа выводимых кадров не гарантирует качество полноценной интерполяции движения.
Видео задерживается примерно на один исходный кадр для получения следующего изображения;
дополнительная задержка звука задаётся в libVLC и сбрасывается при обычном выводе.
При смене серии, перемотке, паузе и изменении параметров история кадров сбрасывается.
На паузе и при отсутствии кадров постоянного цикла вывода нет.

Ошибки EGL/GL, неподдерживаемый вывод декодера, неизвестная частота и устойчивые
пропуски тактов вывода отключают обработку для текущего источника. Плеер возвращается
к обычному выводу с сохранением позиции и паузы. Следующая серия проверяется заново.
Состояние и причина отключения отображаются в технической карточке и журнале.

## Bluetooth-наушники

Заряд показывается с иконкой наушников в правой части верхней панели рядом с загрузкой.
Вся панель скрывается вместе с управлением. Заголовок получает оставшуюся ширину и
не перекрывает индикаторы; техническая карточка учитывает высоту верхней панели.

Источники данных: системные события батареи, публичные HFP-события Apple/Plantronics,
доступный системный getter на совместимых прошивках и BLE Battery Service для уже
подключённых устройств LE/dual. BLE-проверка ограничена таймером, сканирования нет.
При наличии уведомлений заряд обновляется событиями без периодических опросов.
Для классических наушников на Android 4.4, не передающих поддерживаемые события,
проценты получить невозможно: в этом случае показывается «—%». Значение 0% остаётся
корректным значением, а не признаком отсутствия данных. При отключении наушников
индикатор исчезает. Сохранённый процент другого устройства не используется.

На Android 12+ предусмотрено разрешение подключения Bluetooth. При отказе
воспроизведение продолжает работать. Получатели событий, profile proxy и GATT
освобождаются при закрытии/скрытии Activity.

## GitHub Actions

Исправлен сбой `sdkmanager tools` / `Failed to find package 'tools'`.
В `setup-android@v3` явно указаны `platform-tools`, `platforms;android-34` и
`build-tools;34.0.0`; устаревший пакет `tools` не запрашивается.
Build Tools закреплены на 34.0.0. Успешное принятие лицензий не было причиной сбоя.
Перед сборкой APK workflow запускает `testReleaseUnitTest`; отчёты тестов сохраняются
отдельным artifact `tablet-player-unit-tests`.

## Проверка

Локально проверены синтаксис Java, XML, YAML, ссылки ресурсов и используемые API
по исходникам закреплённой зависимости libVLC 3.5.1. Локальная сборка и запуск
Android-приложения не выполнялись. Добавлены JUnit-тесты порога 50 FPS, временного
смешивания 24/25/30 FPS, дробной частоты, порядка PTS/B-кадров и HFP-пакетов батареи.
Эти тесты выполняются в GitHub Actions.

На планшете нужно проверить 24/25/30/48/50/60 FPS, синхронизацию речи, паузу,
перемотку, смену серии, скорость и соотношение сторон, поворот экрана, уход/возврат
в приложение, все три источника видео, а также подключение/отключение наушников.
Фактическая производительность GPU и передача заряда конкретными наушниками
проверяются на устройстве; наличие настройки не гарантирует стабильные 60 FPS.
